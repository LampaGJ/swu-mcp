# swu-mcp

Star Wars: Unlimited (SWU) card data, deterministic card scoring, synergy discovery and card similarity, served to AI assistants over the Model Context Protocol (MCP, stdio). Every number comes from deterministic code over pinned inputs. No model runs at query time and none decides a score.

Status: MVP (swu-mcp#7). All 49 tools below are served and an end-to-end test calls each one over real stdio. One command rebuilds every data product.

## Install

Needs Node.js 22 or newer. Site: https://lampagj.github.io/swu-mcp/.

Claude Code:

    claude mcp add swu -- npx -y github:LampaGJ/swu-mcp

Claude Desktop, in `claude_desktop_config.json`:

    {
      "mcpServers": {
        "swu": { "command": "npx", "args": ["-y", "github:LampaGJ/swu-mcp"] }
      }
    }

npm installs the repository, runs its `prepare` script (an esbuild bundle into `dist/server.js`) and starts the `swu-mcp` bin over stdio. `"private": true` only blocks `npm publish`.

### Data release

The built data (`data/runs/<date>/`, 27 MB raw) is not in git. It ships as a GitHub Release asset, `swu-mcp-data-<date>.tar.gz` (about 2 MB), pinned by `src/data-release.json` (version, URL, sha256, size, build hash). The server picks its data in this order:

1. `SWU_MCP_DATA`: a run directory you name.
2. The newest `data/runs/<date>/` when running from a checkout.
3. A per-user cache, `<cache>/swu-mcp/<dataVersion>/` (`SWU_MCP_CACHE` overrides the cache root). If it is missing, the server downloads the pinned URL, checks the sha256 and size, extracts to a temp directory and renames it into place. A mismatch fails with an error and extracts nothing. `SWU_MCP_DATA_URL` replaces the download URL for testing; the pinned hash still applies.

Progress goes to stderr; stdout is the MCP stream.

To publish new data (the maintainer's step):

    pnpm build:data
    pnpm release:data [--date <YYYY-MM-DD>]

`release:data` writes `tmp/release/swu-mcp-data-<date>.tar.gz` and the pin file, then prints the `gh release create` command. It does not run it. The archive holds `docs` (read by the rubric and glossary resources), `llm`, `features`, `scores`, `synergy`, `market`, `meta`, `rules`, `similarity` and the build records, with sorted entries and fixed times, owners and modes, so the same run gives the same bytes. Commit the pin together with the release.

### From a checkout

    claude mcp add swu-mcp -- pnpm --silent --dir "/path/to/swu-mcp" mcp

`--silent` is required: without it pnpm prints a banner to stdout, which corrupts the MCP stdio stream. The server logs the card count to stderr at start. It also serves the resource `rules://core-primer`, the verbatim core Comprehensive Rules.

Tool results are TOON, a compact table format (column names once, then one line per row), not JSON. Failures set `isError` with a plain sentence. All tools are read-only.

### Remote (for Claude mobile and other hosted clients)

Claude's connectors reach an MCP server by URL, so the stdio server is bridged to Streamable HTTP with [mcp-proxy](https://github.com/sparfenyuk/mcp-proxy) and published over HTTPS by the maintainer's Tailscale Funnel. The bridge is a LaunchAgent, `scripts/bridge/com.swu-mcp.bridge.plist` (copy to `~/Library/LaunchAgents` and `launchctl bootstrap gui/$(id -u) <plist>`), listening on `127.0.0.1:8765` with the endpoint at `/mcp`; the public path is `/swu/mcp` on the maintainer's host. The URL has no authentication: every tool is read-only over public card data. This is the remote endpoint (D54 in docs/decisions.md); a hosted Worker was tried and not pursued.

## Tools (48)

Cards and search

- `get_card` one logical card in full, by `cardKey` or exact title and optional subtitle.
- `search_cards` substring search over title, subtitle and text, narrowed by type, aspect, trait, keyword, set and max cost.
- `list_facet` every value of one facet (aspect, trait, keyword, type, arena, rarity, expansion, variant) with count and definition.
- `cards_by_facet` the cards that carry one facet value.
- `get_cards_batch` up to 50 cards by `cardKey` in one call, with the columns you name.
- `resolve_card_name` typo-tolerant name lookup (MiniSearch fuzzy match, edit distance as tiebreak) to ranked candidate cards.
- `get_printings` the sets a card is printed in with Premier status, variants and the canonical printing's number, rarity and image stem. The package keeps no per-printing rows.

Value

- `score_card` rubric score of one card with a one-line explanation per component and the play-calibrated score.
- `rank_cards` cards ranked by play-calibrated score, total or stat efficiency, with filters.
- `compare_cards` two to five cards side by side.
- `explain_rubric` the formula, vanilla curve, weights, T(cost) and fitted terms with their sources.

Text features

- `card_features` parsed triggers, effects, conditions, offers and wants of one card, clause by clause.
- `find_by_effect` cards that produce an effect category, or whose synergy tags offer or want a fragment.

Synergy and combos

- `find_pairings` enablers that feed a card and payoffs it feeds, with reason, `linkKind` (mechanical, trait+mechanical, trait-only), score, aspect penalty, fungible alternatives (Premier-pool cards that still link with the card through the same row) and the clause text (clipped to 160 characters) behind each offer and want. Mechanical links rank by default; a trait the pair also shares only multiplies its link by 1.1, and pairs that only share a trait come in a separate `tribal` list (5 by default, `tribalLimit`). `traits: exclude` ignores traits, `traits: include` ranks trait-only pairs with the rest. `perLink` (default 3) lists at most that many rows per distinct link before rows that repeat a link, which follow in rank order (`capped` counts them; 100 turns the cap off). An optional `leader` (cardKey or exact title) gives each partner `leaderInclusion` from the leader's tournament decklists (null when unplayed), multiplies the rank by 0.5 + leaderInclusion (0.5 when unplayed; played means 2% or more of the lists, one floor in every tool), defaults `aspects` to the leader's icons and names the population and window. An optional `base` (a Base card, cardKey or exact title; needs `leader`) adds the base's icons to those defaults and is named in the leader block; with a leader alone the block says `base not given: penalties measured against the leader's icons only`. A Leader `cardKey` with no `leader` argument stands in as the leader, with its most-played tournament base as the base, and the leader block says `defaulted: true`; `weighting: none` turns that and the inclusion weighting off, but the aspects stay the Leader card's own icons in every mode, so the cover search never picks another leader. A partner whose clause names a specific base ("While you control a Tatooine base") carries `baseLocked: "Tatooine"` and ranks after every unlocked partner, also past the `perLink` cap, unless the given base has that trait. The `reason` names the side the offer lands on (an enemy unit, your own, or either) where the rule reads differently by side. Every row carries `status: candidate`; `evidence: false` drops the text. With a leader, the leader's own clause is a want source (D60): a partner that meets it (a unit the leader plays, or a card whose text keys on a friendly unit with the keyword the leader gives, such as Boba Fett, Family Found for The Warrior's Ambush) and that the leader's decks play (2% or more) ranks as if they played it in 60% of lists, while an unplayed one takes the plain 0.5 (D65), and the reason quotes the leader clause; `aspects` or `base` is never replaced by the leader's top base, and the leader's lists are narrowed to the given base when at least 10 run it. Besides those two kinds, a unit of power within the leader's limit that gives itself an attack keyword (Raid, Overwhelm, Saboteur, Restore) is a leader-engine row when the leader gives Ambush, an attack on entry (Chewbacca, Resourceful Wookiee; The Chieftain), and a card that readies a leader (Darth Traya) is one when the leader has an Action that exhausts it; each row quotes the leader clause it rests on (D65). The leader-engine rows appear whenever a `leader` is given, also with `weighting: none`, which only drops the play-share factor (D63). Evidence for a tag from the curated table quotes the curated clause, with `source` naming the curated side (D63). With a `leader`, a partner whose clause or cost needs the Force ("use the Force", "while the Force is with you") carries `needsForce` unless the subject, the leader, the base or the deck makes the Force ("The Force is with you"), and a partner whose clause needs a unit of a trait ("While you control another Official unit") carries `needsTrait` unless the subject, the leader or a deck unit has it (or the base meets an "or a Kashyyyk base" alternative); the deck is the optional `decklist` when given, else the cards the leader's lists play (2% floor), and both locks rank the partner after every unlocked one, like `baseLocked` and `nameLocked` (D68). Evidence quotes the cited clause with the trigger and cost it sits under and the clauses it hangs on ("Action [Exhaust, use the Force]: Play a unit from your hand.", "You may use the Force. If you do, ..."), clipped to 160 characters (D68). In a leader-weighted rank the aspect penalty divides the score by 1 + penalty (3 at +2) before the play-share factor, where the plain score divides by 1 + penalty / 2, so a penalty-2 partner no longer outranks a penalty-0 one of similar score (D73). A partner whose own clause names a base location that the given base meets ("While you control a Kashyyyk base, this unit gains Ambush." under Origin Tree) carries `baseEnabled: <Location>` and `baseEnabledClause` and its rank is multiplied by 1.5 (D73). Equal ranks list a deck card first, then the higher play-calibrated score; with a `decklist` each row carries `inDeck` (and `copies`), and `traitGateMetBy` names the deck units that meet the partner's own trait gate (D82). A partner linked both ways is one row (`partnerIs: enabler and payoff`, links joined); a link into a want that checks "this phase" (Koska Reeves) carries `samePhaseCost`, the two printed costs summed; a row reason keeps only the example clauses of the two linked cards (Oppo Rancisis's row no longer explains Marchion Ro); a choose-one quote names its mode ("Choose one (mode 2 of 2): ...") instead of an elision mark, and a cited clause keeps its conditional rider ("If it shares a Trait ...", "For this attack ...") (D83). `traitGateMetBy` reads only the clauses the link quotes, so Choose Your Path's Mandalorian mode names Koska Reeves, not the Force units of its other mode (D84). With a decklist, a link row that gives the wanting card a keyword 3 or more other deck cards (or the leader) already give it counts half: `redundantKeyword` names the keywords and `redundantFactor` the share the score keeps (D85).
- `find_trios` three-card combos (chain, two enablers into one payoff, loop) built from mechanical links and ranked with a bonus for low total cost, each with the clause text behind its links and `status: candidate`. `traits: include` admits trait-only links, but every trio keeps at least one mechanical link. An optional `leader` gives each trio `leaderInclusion` per member and a `rank` that multiplies the score by the geometric mean (cube root of the product) of the member factors, so one played card cannot carry two unplayed ones, and defaults `leaderAspects` to the leader's icons. An optional `base` (needs `leader`) defaults `baseAspects` to its icons and is named in the leader block. A Leader `cardKey` defaults `leader` (and `base` to its most-played tournament base) the same way, and `weighting: none` turns it off (the cover search still uses the Leader card's icons). A trio with a `baseLocked` member follows the others and says which base it needs. A link whose offer is restricted to a trait ("Defeat a friendly Creature unit") appears only in a trio whose third card supplies that trait, as a unit or through the tokens it creates. A Pilot (Piloting attaches to a friendly Vehicle unit), an upgrade with an "Attach to ..." line and a give-token offer that names a trait or keyword ("friendly units with Hidden") feed a "while this unit is upgraded" card only when that card meets the restriction. Each slot's alternatives are Premier-pool cards that keep the slot's links with the other two members, so a substitute never bypasses a trait restriction the slot card met. With a leader-weighted rank, `minPlayed` (0-3, default 2) keeps only trios with that many members the leader's decks play (2% or more of the lists), and the leader block states it. A trio that shares two members with a better-ranked one is folded into it, and its third card is listed under that row's `variants` (title, slot, cost, penalty with fixed aspects, leaderInclusion) when it fills the slot of the member it replaces, every row that member has with the other two (D83). Evidence for a tag from the curated table quotes the curated clause, and `source` names the curated side. A loop whose single-target outlet would have to defeat both the token it is fed and the unit an upgrade in the loop sits on is not a loop (D49). A trio never spends a single-target "defeat a unit" on its own unit as a sacrifice outlet (a sweep or "any number of" still counts); a chain whose single-target outlet would defeat both the token it is fed and the unit it pays off is not a chain; a token made only after a friendly unit was defeated (Koska Reeves) needs another member that defeats one first; a substitutes trio (score 0) follows every scored trio and is never another trio's variant (D76). With a `leader`, a trio whose member needs the Force or a unit of a trait that no member, the leader, the base or the deck supplies carries `needsForce` or `needsTrait` and follows the unlocked trios; the deck is the optional `decklist` when given, else the cards the leader's lists play (2% floor) (D68). With a `decklist` (D71) the search adds a second pool of trios that hold a deck card, so the plain pool's cut cannot drop them, and among the trios no lock demotes a trio that holds a deck card and a card outside the deck (the idea) comes first, then a trio of three deck cards (the build restated), then one with no deck card (D73), and inside a tier a trio whose link into the payoff rests on `ramp-threshold` or `bounce-replay` alone follows the ones with a mechanical payoff, then more deck members (`deckMembers`) before fewer; the decklist alone, with no leader, is the deck the Force and trait locks read; a trio with a Pilot (printed Piloting) and no Vehicle unit among the leader, the deck and the other members carries `needsHost: Vehicle` and follows the unlocked trios. With a `decklist`, a trio whose card from outside the deck brings nothing is not listed: its links rest only on a clause no unit of the deck or trio can switch on (a friendly-trait target such as "attack with a friendly Droid unit"), or another deck card already does each of its links at the same or better standing (D82). With a `leader` whose Action exhausts it, a member that exhausts a friendly leader (Mando's N-1 Starfighter) carries `leaderClash`; with a `decklist`, a member whose rider needs the unit it attacks with to share a trait with another friendly unit (Familiar Strategem), when no unit of the leader, deck or trio does, carries `riderUnmet`; both follow the unlocked trios. `order` names the sort keys, and each idea-tier trio prints `orderRank` (rank x newCardWeight), the key that orders that tier (D83). An upgrade that harms its carrier (Condemn) feeds no friendly upgrade want, a self-only heal or bounce (Oggdo Bogdo, General Grievous) feeds no other card, a defeat of an upgrade or in the regroup phase (Trap Field, Contracted Hunter) feeds no "defeated this phase" want, an offer gated on the attached unit's name (Darth Maul's Lightsaber) feeds only that card, and "If it costs 3 or less, defeat it" reads its pronoun from the clause before (The Tree Remembers defeats an enemy unit) (D83). With a `leader`, `leaderTier` comes first: the cards a deck can hold that the leader's own Action or On Attack feeds (Cad Bane's ping into Oggdo Bogdo, TIE Dagger Vanguard, Rancor Keeper), ranked as `find_pairings` ranks a partner; the trios below keep their order. `riderUnmet` also covers a gift to a unit sharing a trait with a friendly leader (C-3PO, Translation Protocol), a defeat that only replaces the defeat of an upgrade on your base when no Fortify upgrade is in play (Vice Admiral Rampart, A New Era of Safety) and a card that only acts on an enemy token nothing hands the opponent (Lieutenant Gorn). A variant passes the same checks, and one the leader cannot play in place of a member it plays carries `leaderCannotPlay` and follows the others. A trio whose arena-limited attack ("Attack with 2 space units") feeds an upgrade on a unit of the other arena is not listed, and a trio with a penalty prints `penaltyFactor`, the 1 / (1 + penalty / 2) its score already holds. A ready of a non-unit leader (Darth Traya) feeds no unit, a bounce of a unit an opponent controls (Beguile) or of a unit with 6 or more power (Exploit Confidence) replays none of your 2-power units, a want for "a Force upgrade" (Padawan Starfighter) takes no Experience token, and "can't attack unless it's damaged" (Oggdo Bogdo) wants the card damaged (D84). `leaderTier` comes from find_pairings' own rows with the leader as the card, so leader-engine partners (Boba Fett, Family Found; Insurgent Camp) keep their link and generic play links follow; a redundant keyword link counts half (`redundantLinks`); slot substitutes pay no more penalty than the member; an opponent-chosen mode (Watto) never links a trio, a self-defeat rider (Flash the Vents) is a `drawback`, and a trio whose member only "is an upgrade" is not listed (D85). A trio whose every link into its payoff gives that member only what the leader's own Action or On Attack already fills for the round (a damaged gate, a once-each-round ability: Arvel Skeen into Oggdo Bogdo beside Cad Bane's ping) carries `leaderAlreadyFeeds` and follows the trios that add something; with a `decklist`, a trio resting only on generic trigger wants (two extra attacks into one unit) carries `genericLinksOnly` and follows a trio with a specific link; a mode each opponent picks (Giant Gorax) links no trio, a ready of a unit that did not attack this phase (It's Not Over Yet) gives no extra attack, and `leaderTier` copies come from the resolved decklist (D86).
- `explain_synergy` link-by-link reasons why two or three cards pair, with the clipped clause text behind each tag and `status: candidate`.
- `aspect_cover` leader and base aspect combinations ranked by the penalty for a set of cards.

Fungibility and substitutes

- `fungible_substitutes` cards that fill the same role as a card, grouped by aspect, with the role's clause text for the slot card and each substitute and `status: candidate`. A card whose class holds no other member is retried with the cost band relaxed, then with magnitude ignored; `widened` names the step and those substitutes carry `match: widened`. A unit also holds a `keyword:<Keyword>` role per printed keyword (same arena, cost band and power-plus-HP band), listed first for a unit with no offers/wants tag or only a constant "while ..." condition. Substitutes are Premier-pool cards only (a Premier-legal printing). Inside an aspect group substitutes sort by play-calibrated score; give `leader` (cardKey or exact title) and each substitute carries `leaderInclusion`, with the cards that leader's tournament decklists play first. Optional `candidates` (cardKeys or `SET_NNN` ids) are always weighed and listed under `candidates` with score, aspect penalty and `outsideBand: true` when no role lists them; `base` with `leader` (or `preferAspects`) adds the penalty each substitute pays and the card's own; `decklist` leaves cards already in the deck out and counts the keywords it prints as supply; a card that readies a leader or gives a keyword the leader or deck supplies keeps that job (`roleKept`, `keepsRole`, `roleKept.none` when no card does it). Role classes come in order of how much of the card's job they cover (`coverage`, the share of its offers and wants the class's best unlocked card also holds), capped by `maxClasses` (default 8) with `classesCut` and the note saying how many were left out. With `leader` and `base`, a card whose clause needs a base location or a unit aspect they and the `decklist` do not supply carries `baseLocked` or `needsUnitAspect` and ranks after the unlocked cards (D59). The answer has two lists (D69). `partners` holds the cards with a pair edge to the original, marked `feedsOriginal` or `fedByOriginal` with the edge's row (`feedsRow`, `fedByRow`): they work beside the original and are not replacements; a named candidate that is a partner is always listed and `maxPartners` (default 10) caps the rest (`partnersTotal`, `partnersCut`). `standIns` holds the cards that do the original's job without a pair edge to it and never a partner; `roles` and `coverage` count stand-ins only. With `candidates` and a `decklist` the answer adds `recommendation`: for the original and each candidate its aspect `penalty` under the base, its `playShare` in the leader's lists (`leaderInclusion`, or `"unplayed"` under the 2% floor) and `fedByDeck`, the number of cards already in the deck with a pair edge into it (`fedByCards` names them), and a one-sentence `verdict` built from those numbers by the rule it quotes: the card that at least 4 more deck cards feed than the other (a payoff the deck feeds many times over earns a 2-resource penalty, a small gap does not), then lower penalty, then higher play share, then the card already in the deck; when the original wins over a candidate that is its partner, the verdict names that candidate as worth a slot elsewhere and `cutForCandidate` names the deck card to cut for it (highest aspect penalty under the base, then lowest play share in the leader's lists, then fewest pair edges to the rest of the deck, never a card with a pair edge into the original or the candidate; D71). A deck card counts as feeding a card only through the job compared: when a candidate feeds the original's wants, only rows into the same wants count (every `wants:keyword-<k>` row is one job, named in `feederJob`), so a card that readies a unit no longer feeds a keyword payoff. Optional `exclude` (cardKeys, `SET_NNN` ids or titles) drops cards the builder has rejected (D67). `deckLinks` also counts the deck cards tied to a card through The Darksaber it carries or is carried by, named in `carrierLinks` and in the verdict (D84).

Market and play data

- `card_price` US TCGplayer price of one card and its printings.
- `play_stats` Premier inclusion and win figures of one card from the pinned SWU Stats capture.
- `value_vs_price` play-calibrated score per dollar.

Rules

- `rules_core` verbatim text of the core Comprehensive Rules; read first for any rules question.
- `rules_search` ranked keyword search over the rules sections.
- `get_rule` one section by id, with children, parent and cross-references.
- `card_rulings` dated official rulings for one card.
- `keyword_rules` a keyword's definition and the rules sections that define it.
- `rules_version` which Comprehensive Rules the rules tools use.
- `search_rulings` card rulings filtered by text, keyword and date. No filter by rules section.

Sets and legality

- `list_sets` every expansion with kind, main set number, stated release date and Premier status, parsed from the expansion notes.
- `format_legality` Premier, Eternal and Twin Suns legality of a card with the reason. Set-based and current only: no ban list or legality history is in the data.

Similarity

- `similar_cards` cards whose rules text reads most like this card's (embedding cosine).
- `kin_cards` cards that do the same kind of thing under different labels (names, traits, keywords, aspects and numbers masked).
- `cluster` one of 32 role clusters, by id or by a member card.

Decks, collections and trades (lists arrive as `{card, count}` arguments, a cardKey or exact title; nothing is stored, unresolved names are listed)

- `deck_audit` one-call report on a decklist under a leader and base: curve against the rubric's stat curve, mean score, aspect penalty per card, orphan wants and role-cluster gaps. When the package holds the leader's tournament decklists, `leaderComparison` lists the staples the deck lacks (inclusion 0.5 or more) and the deck cards those lists rarely play (under 0.05, or never), and cluster gaps are measured against the leader's played cards instead of the whole pool; clusters of bases, leaders or tokens are skipped. Generic wants (any When Played, On Attack or When Defeated) come as one `genericWants` line, not one orphan row each. With the leader's decklists, an orphan's named feeders are the cards those lists play (2% or more) first, most played first, then by aspect penalty, and an unplayed feeder is marked `unplayed`. A cluster gap's `deckCards` counts a deck card when the clusters file places it in the cluster or it carries a tag that defines the cluster (the `norm` line states the rule). Takes the deck as a `swudb` argument, the SWUDB JSON interchange document (exports of SWUDB, melee.gg, Karabast and SWU Stats, ids like `HMW_018`), instead of `decklist`, `leader` and `base`; a `SET_NNN` id also works in any `card`, `leader` or `base` field. A document's sideboard is listed under `sideboard`, one row per card, apart from the deck counts. With the leader's decklists the staples follow the given base (D60): the lists with that base (or its aspect) are used when at least 10 remain, else all of them, and `populationNote` says which and why (counts and the dominant base); a staple that pays an aspect penalty under the leader and base carries `penalty` and `penalised: true` and is listed, not hidden. A card that removes an aspect penalty is read from card text (decision D75): The Darksaber (the attached unit provides its icons while you pay costs) and a leader, base or deck card that says "ignore the aspect penalties on ... you play" give the covered rows of `aspect.uncovered` a `removedBy` and an `effectivePenaltyEach`, while `penalty` stays the printed figure. `clusterGaps.gapCards` names, per shown gap, the top three cards of the cluster the deck lacks, with cost, penalty and the share of the leader's decklists that play them. Unplayed orphan feeders list an in-colour upgrade that attaches to the card first (D82). A Darksaber carrier that pays an aspect penalty of its own is named as a taxed carrier: the first one played pays its penalty, later ones pay `effectivePenaltyEach` while the Darksaber stays on it (`sequenced: true`), and `aspect.sequence` gives the best-case and worst-case totals of those cards (D83). A cost holding more than 40% of the costed cards is named under `curveGlut` (the Warrior list: 25 of 50 at cost 3), with the thin costs from 2 to 6 and up to 3 untaxed in-colour fills per thin cost that the deck lacks, most played by the leader's lists first (Kelleran Beq at 4, Lightmaker at 5) (D84). `curveGlut.leaderAction` says when the glut sits in the leader's Action band (The Warrior plays a unit of 3 or less power for 1 more resource), and fills rank by `fillRank` = (1 + `deckLinks`) x (0.5 + 3 x leaderInclusion) (D85). `deckLinks` counts only specific links (a row into a generic want such as extra attacks does not count), and a fill the leader's own engine reads (`leaderEngine: true`, Commander Gree under The Warrior) comes first within its cost, before `fillRank` (D86).
- `deck_legality_check` exactly 1 leader and 1 base, 50 other cards (or the base's changed minimum), 3 copies at most, no tokens, Premier cardpool, each failure with its Comprehensive Rules section (9.2.2.a to d, 8.5.5, 1.2.3, 3.2.1.a). `counts.listedCopies` counts every listed copy, unresolved lines included. No ban or suspension ledger and no asOf date. A sideboard (from `swudb`) is checked for its 10-card limit, its card types and, in Premier, the cardpool (D83). Takes the deck as a `swudb` argument, the SWUDB JSON interchange document (exports of SWUDB, melee.gg, Karabast and SWU Stats, ids like `HMW_018`), instead of `decklist`, `leader` and `base`; a `SET_NNN` id also works in any `card`, `leader` or `base` field.
- `suggest_leader_base` leader and base aspect pairs ranked by the penalty for a pile of cards.
- `playable_cards` the best cards for a leader and base, by cost, optionally filling the costs of a partial pile. Within a cost, cards that this leader's tournament decklists play most come first (`leaderInclusion`, with the population and window named), then the play-calibrated score; `rankBy: "score"`, or a data package without `meta/leader-cards.json`, ranks by score alone. In leader mode a card in 60% or more of the leader's decks is a staple: it is always listed in full, even past `perCost` and `limit`, marked `staple: true` and counted toward neither; `limit` caps the other rows, so a long page still reaches the high costs. A card in under 2% of the decks, or none, is left out unless `includeUnplayed: true`, and the `emptyCosts` line names a cost left with no played card (`no tournament-played card (>= 2%) at cost N`). With `emptyCostsOnly` only a cost where the leader's lists hold at least 0.5 mean copies is reported; `emptyCosts` names the others in one line (`under 0.5 mean copies in the leader's lists at costs 0, 9, 10`). Takes the deck as a `swudb` argument, the SWUDB JSON interchange document (exports of SWUDB, melee.gg, Karabast and SWU Stats, ids like `HMW_018`), instead of `decklist`, `leader` and `base`; a `SET_NNN` id also works in any `card`, `leader` or `base` field. With the leader's decklists the staples follow the given base (D60): the lists with that base (or its aspect) are used when at least 10 remain, else all of them, and `populationNote` says which and why (counts and the dominant base); a staple that pays an aspect penalty under the leader and base carries `penalty` and `penalised: true` and is listed, not hidden. A staple that `maxPenalty` drops is listed under `penalisedStaples`. A card whose own clause names a base location that the given base meets ("While you control a Kashyyyk base, ..." under Origin Tree: Soaring Can-Cell, Overgrowth, Wookiee Rangers, Origin Tree Shyyyo) carries `baseEnabled: <Location>` and `baseEnabledClause`, ranks first within its cost after any locked card, and is listed even when the leader's lists play it under 2% (D73). Each row carries `evidenceClass` from the same tournament deck evidence `meta_answers` reads (`evidenceGap` when negative), and a measured-negative card comes last within its cost (Ahsoka Tano, Chasing Whispers under The Warrior) (D86).
- `fungible_in_deck` same-role substitutes per deck slot, least aspect penalty first; only Premier-pool cards (a Premier-legal printing). Takes the deck as a `swudb` argument, the SWUDB JSON interchange document (exports of SWUDB, melee.gg, Karabast and SWU Stats, ids like `HMW_018`), instead of `decklist`, `leader` and `base`; a `SET_NNN` id also works in any `card`, `leader` or `base` field.
- `budget_alternatives` cheaper same-role substitutes with the saving and the score change. With a leader and base, a substitute never carries a higher aspect penalty than the card it replaces, and substitutes sort by the leader's tournament inclusion first (`leaderInclusion`); a slot with no played substitute (under 2% of the lists) says `no tournament-played substitute under the cap`. With `maxPrice`, a card already at or under it is skipped and listed in `alreadyUnderCap`. A priced card with no swap is listed in `noAlternative` (card, price, reason: `no cheaper same-slot card`, the role no card in the cost band fills when band cards exist (`no card in the cost band fills offers:resource-ramp`, D83), `no card within the cost band`, or the card's job when it keeps one, for example `no card readies a leader`), so every priced card sits in `slots`, `alreadyUnderCap` or `noAlternative`. A substitute has the card's type, a unit's arena and a cost within 1 of the card's, and a Premier-legal printing (a card only in rotated or unverified sets is left out). `savingPerCopy` is the best single swap on one copy; `totalSaving` sums every slot's first swap times its copies. Takes the deck as a `swudb` argument, the SWUDB JSON interchange document (exports of SWUDB, melee.gg, Karabast and SWU Stats, ids like `HMW_018`), instead of `decklist`, `leader` and `base`; a `SET_NNN` id also works in any `card`, `leader` or `base` field. Optional `candidates` (cardKeys, `SET_NNN` ids or titles) are weighed against every deck card they share a role with and listed under `candidates` with price, saving, score, penalty and `outsideBand`; a card that readies a leader or gives a keyword the leader or deck supplies keeps that job in its swaps, and so does a unit that readies a unit, draws a card or removes an enemy unit (`job`, `keepsRole`; `noAlternative` says when no card does it, or none is cheaper: `no cheaper same-slot card that readies a unit`). With a leader and base, a substitute whose clause needs what the leader, base and decklist do not supply (the Force, a trait, a base location, a unit aspect, a named card) carries the lock (`needsForce`, `needsTrait`, `baseLocked`, `needsUnitAspect`, `nameLocked`) and sorts after the open substitutes of its slot (D75). An upgrade's substitute fills every role of the upgrade it replaces (D82). A substitute that gives the opponent a resource, a card or a token carries `drawback`, the clause quoted (Display Piece) (D83), and so does one that damages your own base (Boba Fett's Rancor). An event that removes a unit keeps that job like a unit, and a removal swap capped by cost, power or HP carries `limit`, the clause quoted (The Tree Remembers: "If it costs 3 or less, defeat it.") (D84). A damage removal swap's `limit` names the damage and target restriction ("2 damage, unique units only"), a unit that creates token units or holds Sentinel keeps that job, and a swap the opponent may replay from the discard carries `drawback` (D85). The `limit` names every damage mode (The Cyborg Mech: "2 damage, ground units only, undamaged units only; or 5 damage, ground units only, damaged units only") and adds damage dealt again to the same unit (Boba Fett's Rancor: 10 damage) (D86).
- `price_list` total US price of a deck or collection, with the top share and totals by first set, rarity, aspect or type.
- `trade_balance` two lists compared by market price, low price and rubric score.
- `owned_vs_needed` a decklist against an owned list: missing copies, cost to complete, owned substitutes. Takes the deck as a `swudb` argument, the SWUDB JSON interchange document (exports of SWUDB, melee.gg, Karabast and SWU Stats, ids like `HMW_018`), instead of `decklist`, `leader` and `base`; a `SET_NNN` id also works in any `card`, `leader` or `base` field.
- `play_value_vs_price` cards most or least played per dollar, from the SWU Stats capture.
- `score_vs_play` cards whose rubric rank and play rank disagree (the designer total by default, because the play-calibrated score is fitted to the same play data).

Meta defense (every win rate comes from swumetastats tournament data, melee.gg events, with its window, n and a 95% interval; community lists are a labelled secondary view of archetype shares)

- `meta_archetypes` the current Premier archetypes: tournament decklists from the last 90 days of the newest snapshot (placement-weighted), clustered by leader, base aspect and shared core cards, with meta share, top-8 share, the date window, the leader and base aspect's tournament match record (n and 95% interval), threats, core cards and the most-played base (`topBase`). Community lists are a separate population, and the fallback when a window holds too few tournament decks.
- `meta_threats` one archetype in depth: bases, arena split, curve, keywords, upgrade and token reliance, key units with cost, power and HP, core cards with inclusion rates, threats and its tournament record against the field and against each other large archetype (leader and base aspect matchups, with n and 95% interval). The `faces` block (`facesLimit`, default 6, 0 leaves it out) lists the largest archetypes of the tournament population with this leader's wins, losses, draws, win share, 95% interval and n against each, and `no measured matchup (n < minN)` where fewer than `minN` decisive matches exist; a community archetype found by fallback still faces the tournament meta (D63). `key-units` fires only when two or more units at cost 6 or more are played by at least 80% of the archetype's decks (`profile.heavyKeyUnits`, D63). A leader with no tournament archetype in the window falls back to its largest community archetype, labelled `leaderSource` (`population: community`, `fallback: true`, `decks`) and never pooled with tournament decks; the error, naming both deck counts, appears only when neither population holds a deck. `base` with a leader cardKey profiles the archetype with that base's aspects.
- `meta_answers` cards in our aspects that answer the largest archetypes, penalty-free first, from a leader and base or a decklist: the threats each answers with clause evidence and `status: candidate`, coverage weighted by meta share, cost, copies already in the deck, and tournament deck evidence: the match win rate of comparable decks (same leader and base aspects, else same aspect set) with the card against those without it, with n, 95% interval, source and window. Opponents are not known per match, so this is not a rate against any archetype. Each answer carries `leaderInclusion` (the share of our leader's tournament decklists that play it, null when unplayed); within a coverage band, evidence class and cost band the more-played answer ranks first, and the page leaves out answers under 2% unless they are already in the deck or `includeUnplayed: true` (`capped` counts them). A conditional Saboteur gained on the card itself (Marrok) counts for sentinel-wall and shields at weight 0.5, with the condition in the evidence. A card with an open offer and a locked clause (`baseLocked` or `needsUnitAspect`, such as Sandcrawler Sales Team under Origin Tree) ranks after every unlocked answer, also past the `perThreat` cap (D65); the locked clause counts whether or not an answering offer rests on it (Ritual Dragon: printed Saboteur open, a Tatooine clause that answers nothing, D71). `perThreat` (default 4) lists at most that many answers per primary threat before answers that repeat a threat (`capped` counts them), and `threatsCovered` counts the shown answers per threat the defended archetypes pose (staples and additions together). `minPerThreat` (0-5, default 1) reserves a page slot for the best answer of every fired threat before the rank fill, taking an answer under the 2% floor when nothing above it answers (`reserved: true`, `hiddenByFloor: true`), so a threat reads 0 only when no answer exists in the pool. The output splits into `staples` (already in the deck, or played by 50% or more of the leader's lists) and `additions` (the rest, so a builder sees what to add first; `limit` applies to these). An answer whose every offer defeats or damages all or each unit of both sides (a sweep such as Single Reactor Ignition) carries `symmetric: true` and sorts after the other answers of its coverage band when the decklist runs 30 or more units or the leader's lists average more than 30 (`symmetricSweeps` states the count). The answer relations are the committed table `data/counters.json`. A deck-evidence figure whose decks without the card number fewer than the smaller of 10% of the comparable decks and 50 decks reads `evidenceClass: thin-control` (`deckEvidence.thinControl`: the decks without this card are N of M comparable decks: not a control group) instead of ok. With the leader's decklists `leaderInclusion` follows the given base (D60): the lists with that base (or its aspect) are used when at least 10 remain, else all of them, and `populationNote` says which and why (counts and the dominant base); a staple that pays an aspect penalty under the leader and base carries `penalty` and `penalised: true` and is listed, not hidden. An addition whose deck evidence is negative, a thin negative included, is listed after every addition whose evidenceClass is ok, whatever its coverage (D75). A negative staple follows the last ok staple, an addition measured with a significant gain (`significant: true`) is listed before every unmeasured addition, and a choose-one answer quotes its whole mode (D82). Among the staples every ok row, significant or not, comes before every unmeasured one; `meta_answers` also takes the deck as a `swudb` argument, and an answer the document's sideboard holds carries `inSideboard` (D83) and is listed under `sideboardAnswers`, never among the additions; a thin-control staple follows the last significant staple (D84). Every threat a card answers adds its strongest answer (Chimaera's choose-then-defeat removes key units beside its heal); a measured-negative addition takes no slot and is listed under `negativeAdditions`; an addition carries `drawback` like a budget swap (Stolen AT-Hauler) (D85). An offer gated by its ability's own header ("If you control an Endor base, each opponent chooses one:") is locked by that gate, and a mode an opponent picks answers nothing: a card with no other answer goes under `lockedAnswers` at coverage 0 with `opponentChooses` quoted (Giant Gorax) and takes no reserved slot; with a decklist, a conditional answer whose condition no other deck card, the leader or the base feeds carries `conditionUnfed` and holds no threat's reserved slot alone (Marrok, so Orbiting K-Wing is reserved for sentinel-wall); one-sided go-wide removal counts as a sweeper (Pre Vizsla's "total of 6 or less remaining HP" when it takes two typical cheap units; "each of up to 3 units") (D86).
- `leader_cards` the cards a leader's decklists actually play: every card in all of the leader's decks in the meta window (tournament decklists; community lists only when the leader has no tournament deck, and the output says so), with placement-weighted inclusion, mean copies, baseline inclusion across the decks whose leader and base aspects could play the card, and lift over that baseline. `sortBy` is `inclusion` (raw popularity) or `lift`; the output names the population, window and deck count, with `status: fact`. Optional `base` narrows the lists to that base (or its aspect) when at least 10 run it, else uses all of them and says so in `populationNote`; each card then carries `penalty` and `penalised: true` when it pays an aspect penalty under the leader and base. With `base`, every row also carries the lock it meets under that base (`baseLocked`, `needsUnitAspect`, `nameLocked`, `needsForce`, `needsTrait`) beside `penalty` and `penalised: true` (D75).

## Data pipeline

One command rebuilds every data product from mault's originals:

    pnpm build:data [--originals <dir>] [--date <YYYY-MM-DD>]

It runs these steps in order and stops at the first failure:

- `export:package` the raw card-list pages and price files to `llm/` (cards, facet indexes, name index), `docs/` and `replay.json`. It verifies every page against the manifest hashes first.
- `card-features` parses every card's text into triggers, effects, offers and wants (`features/`), and adds each base's printed location to its traits from the pinned capture in `data/pinned/base-locations/` (`pnpm tsx scripts/pinned/capture-base-locations.ts --engine <forceteki clone>` makes it; the official API ships bases with empty traits).
- `score` the deterministic rubric scores (`scores/`).
- `synergy` pairs, trios and fungibility classes (`synergy/`).
- `market` prices and play statistics (`market/`).
- `rules:fetch` the Comprehensive Rules sections, card rulings, keyword links and the core primer (`rules/`). It reads the pinned PDF under `data/originals/rules/<version>/` when one exists and downloads it otherwise.
- `similarity` similar, kin, clusters and vectors from the pinned embedding capture (`similarity/`). No model runs here; `pnpm embed:capture` is the one model call and its output is pinned in `data/pinned/embeddings/`.
- `meta` archetypes and win-rate aggregates (`meta/`) from the newest deck snapshot under `data/originals/decks/<date>/`, and the pinned tournament matchup capture under `data/originals/tournaments/<date>/` (`pnpm meta:capture-matchups`, once). Premier decks only. Card evidence rows need 10 or more decisive matches both with and without the card. Both inputs are git-ignored; their hashes go into `meta/replay.json`. The step reads no Karabast data: `meta/` ships in the data release.

Output goes to `data/runs/<date>/` (git-ignored). `build.json` there records each step's replay hash, the sha256 of every output file, the code commit and the wall time. The `buildHash` in it covers the replay hashes (code commits removed) and every output hash, and leaves out the code commit and wall times, so two builds of the same inputs have the same `buildHash`. Individual steps can still run alone, for example `pnpm score`.

Every step is a replayable transform: deterministic code, pinned inputs, byte-identical output. Model output enters only as captured, hashed input.

## The data package

    pnpm package:zip [--data <run dir>] [--out <dir>] [--no-zip]

Assembles the zip for readers (default destination: the iCloud `_temp` folder) from a built run. It is staged under `data/packages/<date>/` first. The zip is deterministic: the same build gives the same bytes. Layout:

- `README.md` the entry point: what each file is for, the image URL prefix, how files join, what to load first, honest limits.
- `llm/` everything a reader loads: `cards.toon` with `playCalibrated`, `total` and `cluster` columns; `legend.toon` (every definition, shipped once); `index/` with the facet indexes, names, `similar`, `kin`, `clusters`, `pairings` (top 10 per card), `trios` (top 200 per shape, total cost 9 or less) and `fungible` (classes with at least two members); `rules/` with the core primer and the dated card rulings.
- `optional/vectors.toon` 128-dimension int8 vectors, with the decode recipe in the zip README.
- `audit/` build records, JSON Schemas, the list of printing disagreements and the rubric derivation. A reader can skip it.
- `docs/` the card data field guide and a rubric summary.

`audit/package.json` in the zip lists the sha256 and token count of every file. Token counts use gpt-tokenizer `o200k_base`, a proxy, and are dev-only.

## Honest limits

- Pairings, trios and fungible substitutes are candidates, not facts. Sampled reviews ([round 1](docs/verification/2026-10-16.md), [round 2](docs/verification/2026-10-17-round2.md)) found card-text features wrong on about 1 card in 5. On the committed 200-pair benchmark ([pairs-v1](docs/verification/2026-10-17-pair-fixture.md)), about 79% of pairings are genuine (95% interval 73–84%), so about 1 in 5 is wrong; mechanical links alone are 76% (69–82%) and trait links 94% (80–98%), and some rows (discard, draw, ramp) are much weaker. `pnpm verify:pairs` re-measures it. About 1 pair in 5 (16,112 of 74,530) links two cards only through a shared trait; those tribal links are obvious and mostly right, so the pairing and trio tools rank mechanical links by default and list trait-only pairs apart. Against real play ([real-play benchmark](docs/verification/real-play-2026-10-17.md)), whose headline figures leave trait-only pairs out, suggested pairs appear together in 32,699 Premier decklists (December 2025 to October 2026, mostly tournament) more often than matched random partners (0.08 log-lift, card-clustered 95% interval 0.04–0.12; trait-only pairs alone 0.67), a modest margin; the pair score does not rank them by how often they are played together (#22). Confirm a pairing against both cards' text before relying on it. Copied data is exact: card fields, rulings, prices, play stats and rules sections passed a full deterministic audit against the originals with no failures.
- Meta answers are candidates. The counter table checks parsed cost, HP, power, arena and trait limits against each archetype's key units, and a removal target with a condition it cannot read never counts; parsed card text is still wrong on about 1 card in 5. The deck evidence beside each answer is association, not effect: decks that run a card may differ in pilots and in the rest of the list, and swumetastats publishes no per-match pairings, so a deck's record is against its whole field. A local-only benchmark ([method](docs/verification/meta-defense-2026-10-17.md)) checks the answers against private game outcomes; its numbers are not published.
- The play data is thin. It is online Karabast and Petranaki games in three Premier windows, not tournaments. Homeworlds (HMW) has under one week of play data and is outside the play fit.
- Prices mostly follow rarity. They are US TCGplayer prices from one import, so cheap commons dominate any value-per-dollar ranking.
- `total` is comparable only within a card type. `playCalibrated` is rank-meaningful only and is fitted to the same play data it is compared with, so a gap between score and play is partly circular.
- The Comprehensive Rules version check is manual: run `pnpm rules:check` (exit 0 current, 10 newer available, 2 error). Nothing schedules it.
- The scope is the logical cards with a printing in Jump to Lightspeed or a later set, which matches Premier legality.
- Base locks come from the location printed on each base, pinned from the forceteki engine's card data (decision D59). Every one of the 69 bases in the card table has a pinned location; no base is without one. A lock is read only from a card's own clause text: a lock in a leader or base ability is not flagged, and the cluster gaps of `deck_audit` do not look at locks. An aspect-unit lock counts the leader's, the base's and the deck's aspects as supplying a unit, although a base is not a unit.

It reports deck co-inclusion lift and leader-stratified win-rate differences per complementarity row, each against matched random partners. A human-game analysis also runs, but its figures stay in a local git-ignored report and are not published (decision D22 in [docs/decisions.md](docs/decisions.md)).

## Layout

- `src/` the MCP server. `server.ts` is the stdio entry, `data-source.ts` resolves and downloads the data, `data-release.json` pins the release, `create-server.ts` registers the tools, `tools.ts` and `tools/` hold the handlers, `data.ts` loads and validates the package.

- `scripts/` one script per step, `build-data.ts`, `package-zip.ts`. `scripts/curation/`, `scripts/rubric/` and `scripts/embed/` are research scripts.
- `data/curated-rules.json` the curated ability table and `data/complementarity.json` the pair table (pinned inputs). `data/pinned/` small pinned captures with hashes. `data/runs/<date>/` and `data/packages/<date>/` generated output (git-ignored).
- `docs/` field guide, JSON Schemas, glossary, value rubric and the tool catalogue (`docs/mcp-tool-catalogue.md`).
